# 地址簿与设备分组技术方案

**状态**: 已完成（服务端、OpenAPI/SDK、Web 和 Qt 均已验收）  
**对应需求**: QD-204 / 上游 Roadmap `Address book & device groups`

## 1. 目标

QuickDesk 已有管理员级设备分组，但它回答的是“平台怎样管理所有设备”，不是“一个用户怎样整理自己的设备”。QD-204 增加 owner-scoped 地址簿：

- 每个用户自己创建、命名、着色和删除分组；
- 分组只能包含当前用户名下的设备；
- 用户可以从设备页按分组筛选；
- 分组数据不会暴露给其他普通用户；
- 功能可以作为独立上游 PR，不依赖 Remoting 或 Chromium 重编译。

## 2. 不采用的做法

### 2.1 直接给 `device_groups` 加 `owner_id`

现有 `device_groups` 是管理后台的全局设备库存模型，名称全局唯一，管理端接口也按全局
范围查询。直接改表会同时改变管理员语义、唯一约束和现有 Web 管理后台，风险大于收益。

### 2.2 只做前端本地分组

本地分组无法跨设备、跨浏览器同步，也无法成为上游可复用的控制面能力，不符合
“最后共享给上游”的目标。

### 2.3 复用收藏作为分组

收藏是一台设备一个书签，并且可以保存访问密码；分组是多设备集合。两者生命周期和权限
边界不同，不能把收藏表改造成多对多关系。

## 3. 数据模型

新增两张 owner-scoped 表，与管理员 `device_groups` 并存：

### `user_device_groups`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 所有者，外键到 `users`，删除用户时级联 |
| `name` | 100 字符以内，同一 owner 内唯一 |
| `description` | 500 字符以内，非空列，缺省为空字符串 |
| `color` | 20 字符以内，非空列，缺省为空字符串 |
| `created_at` / `updated_at` | 审计时间 |

唯一约束为 `(user_id, name)`，不同用户可以使用同一个分组名。

### `user_device_group_members`

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `group_id` | 外键到 `user_device_groups`，删除分组时级联 |
| `device_id` | 外键到 `devices`，删除设备时级联 |
| `created_at` | 加入时间 |

唯一约束为 `(group_id, device_id)`。服务层在写入前校验设备当前归属，拒绝把其他用户的
设备加进分组；一个分组最多包含 500 台设备，超过上限整次替换失败。

## 4. API

用户接口统一位于 `/v1/me/device-groups`，需要用户 Bearer token：

| 方法 | 路径 | 语义 |
|---|---|---|
| `GET` | `/v1/me/device-groups` | 列出当前用户分组和 `device_ids` |
| `POST` | `/v1/me/device-groups` | 创建分组 |
| `PATCH` | `/v1/me/device-groups/:group_id` | 改名、描述或颜色 |
| `DELETE` | `/v1/me/device-groups/:group_id` | 删除分组及成员关系 |
| `PUT` | `/v1/me/device-groups/:group_id/devices` | 原子替换整个成员集合 |

成员更新使用 `PUT` 而不是逐条 add/remove：前端保存一次完整勾选结果，服务端在一个事务里
校验归属、清空旧成员、写入新成员，避免多条请求中途失败导致半个分组。

返回对象：

```json
{
  "id": 12,
  "user_id": 3,
  "name": "Office",
  "description": "Weekly maintenance",
  "color": "#1f6feb",
  "device_ids": ["126735214"],
  "device_count": 1,
  "created_at": "2026-10-17T07:00:00Z",
  "updated_at": "2026-10-17T07:00:00Z"
}
```

## 5. 权限与生命周期

- `List/Create/Update/Delete/ReplaceDevices` 全部以 `middleware.MustUserID()` 为用户边界。
- 查不到分组时统一返回 `404 DEVICE_GROUP_NOT_FOUND`，不区分“不存在”和“属于别人”。
- 成员里有任何设备不属于当前用户时，整个 `PUT` 拒绝为
  `403 DEVICE_NOT_OWNED`，旧成员保持不变。
- 设备被用户解绑或转交给别人时，`DeviceService` 在同一事务里清理旧 owner 的分组关系，
  防止设备以后回到旧 owner 时留下幽灵成员。
- 管理员全局分组接口保持原样，不作为用户地址簿的授权来源。

## 6. 客户端

### WebClient

- 设备页增加分组筛选；
- 分组管理对话框支持创建、编辑、删除和成员勾选；
- 成员保存失败时只显示错误，不提前替换本地成功状态；
- 复用现有 `showToast`、i18n 和移动端布局。

### Qt

- 新增 `DeviceGroupManager`，复用现有用户 API Bearer 认证；
- 我的设备页增加分组筛选和“管理分组”入口；
- `DeviceGroupManagerDialog` 支持创建、编辑、删除、颜色、描述、成员多选和整体保存；
- 成员保存失败时保留服务端已有分组状态，不把乐观结果当作成功；
- `quickdesk_device_group_manager_test` 覆盖列表归一化、CRUD、成员替换、设备不属于当前
  用户时的失败状态，并断言管理器不会调用管理员 `/v1/admin/groups`。

## 7. 上游贡献

这一项可以拆成两个独立上游增量：

1. **服务端/API/SDK**：数据表、service、handler、OpenAPI、生成客户端、contract smoke；
2. **客户端**：WebClient 和 Qt 的地址簿入口。

前提是上游 PR #25 的控制面和 OpenAPI/SDK 基线已确认。若 #25 尚未合并，客户端 PR 明确
声明依赖，不把整个 fork 文档或品牌页面塞进上游。
